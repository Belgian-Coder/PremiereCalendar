# v1.2.20 - calendar reliability and local container qualification

## Changes

- Calendar day-window moves no longer overlap while browser measurement is
  pending. Stale completions are ignored, with scrolling, timing, layout and
  accessibility checks retained.
- IMDb ratings are read without losing decimal precision, so a title rated
  7.6 remains eligible for a minimum rating of 7.6.
- Local build and release helpers use bounded process transport and exact
  source/image/archive bindings. Mutable build state stays isolated by checkout,
  Linux ABI, runtime mode and watcher/check lane; pure package caches keep their
  coordinated extraction locks.
- SDK CLI/plugin metadata uses a marked subdirectory of that build storage.
  FreshBuild keeps it container-local; unknown existing state is preserved and
  refused. Restores remain noninteractive and do not generate HTTPS certificates.
- Validation, tests, builds, CI, scans and packaging run locally. The former
  GitHub Actions entrypoints are removed; self-hosted Actions orchestration is
  also prohibited. Accepted artifacts are uploaded from the local builder.

## Breaking and operational changes (since 1.2.19)

- SQLite, the Windows service, installers and the self-updater are removed;
  the app is PostgreSQL-only and ships only as a container. Installations that
  still hold a SQLite database must first migrate with 1.2.19 (the last release
  with `database migrate-postgres`), then upgrade.
- Startup fails with an explicit error when `AppDatabase:Path` is set or
  `AppDatabase:Provider` is anything other than `PostgreSql`; the deploy step
  now refuses a stack that still carries either setting. The NAS stack was
  checked: it uses `PostgreSql` and sets no path.
- The `database snapshot`, `database restore` and `database migrate-postgres`
  commands are removed; `database verify` and
  `database prepare-legacy-checkpoints` remain.
- A relative `AppDatabase:PasswordFile` resolves against the content root,
  not the working directory; a missing or unreadable password file stops
  startup.
- Provider responses are capped at 16 MiB decoded (64 MiB for SIMKL library
  pulls); an oversized response fails that request and is logged without its
  query string.
- Provider clients negotiate gzip, deflate and Brotli. The application is
  compiled with .NET 11 runtime-async (opt out with `-p:UseRuntimeAsync=false`).
  Package updates: Npgsql 10.0.3, OpenTelemetry 1.21.0, Magick.NET 15.1.0; the
  Windows-service and SQLite packages are gone.
- The database schema stays at version 4, so an app-only rollback to 1.2.19
  remains possible.
- Browser acceptance (desktop/mobile calendar contract, accessibility and
  timing budgets) is run on the exact release commit with the prepared browser
  image and recorded in the bundle and review record; the release gates
  themselves still require only the unit, component and integration suites.

## Faster local validation, tests and release

- `eng/Invoke-StaticChecks.ps1` runs the portable static lane (Windows 11 and
  macOS) in parallel; `eng/Invoke-Validation.ps1 -Changed` runs only the checks
  that cover the changed files and lists or runs the scoped app commands.
  Python discovery no longer breaks when several interpreters are on PATH.
- The harness tests reuse Git fixtures and run independent groups concurrently.
- The test runner builds all selected suites in one MSBuild pass, starts
  PostgreSQL while the build runs, defaults to half of the engine's CPUs and
  scales its deadline with the selected suites. Bounded cleanup calls now
  tolerate a loaded engine instead of leaking the disposable containers.
- Integration tests share one web host per class; oversized unit fixtures and
  synthetic delays were reduced; five obsolete or redundant tests were removed
  (the Windows-only file-lock test, a duplicated checkpoint size row, a
  source-text grep and two framework-equivalence checks). Batch-window tests
  order their callers explicitly instead of relying on timing.
- Release steps reuse a labelled Trivy database cache (with a 48-hour freshness
  gate) and a NuGet package cache (vulnerability data stays uncached), run
  Trivy and Syft concurrently, and restore through a BuildKit cache mount.
  `eng/release/Invoke-LocalGates.ps1` runs steps 2-7 with safe concurrency and
  records `gates/stage-timings.json`.
- The runtime image upgrades `libcrypto3`/`libssl3` to `3.5.9-r1` or later
  because the pinned base still ships `3.5.9-r0`.

## Release boundary

This is a prepared Linux/amd64 Docker release for the existing NAS installation,
not a native Windows or Mac installer. The source schema version remains 4.
The release version is supplied to `Initialize-Release.ps1`; local development
version defaults are unchanged. See [Releasing](../Releasing.md) for the
canonical source freeze, fresh backup/restore, full service/browser, security,
exact-image, upload, installation and rollback gates.

Build, qualification, publication and installation are pending. Historical
029/DF/SDK/fixture receipts do not qualify this release. Installed acceptance
will be recorded only after the exact release passes its gates and is verified
on the approved target.
