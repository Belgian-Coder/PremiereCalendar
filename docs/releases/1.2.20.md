# v1.2.20 - calendar reliability and local container qualification

## Changes

- Calendar day-window moves no longer overlap while browser measurement is
  pending. Stale completions are ignored, with scrolling, timing, layout and
  accessibility checks retained.
- IMDb ratings are read without losing decimal precision, so a title rated
  7.6 remains eligible for a minimum rating of 7.6.
- Local build and release helpers use bounded process transport and exact
  source/image/archive bindings. Mutable build state stays isolated by checkout,
  Linux ABI, runtime mode and watcher/check lane; pure package caches keep their
  coordinated extraction locks.
- SDK CLI/plugin metadata uses a marked subdirectory of that build storage.
  FreshBuild keeps it container-local; unknown existing state is preserved and
  refused. Restores remain noninteractive and do not generate HTTPS certificates.
- Validation, tests, builds, CI, scans and packaging run locally. The former
  GitHub Actions entrypoints are removed; self-hosted Actions orchestration is
  also prohibited. Accepted artifacts are uploaded from the local builder.

## Release boundary

This is a prepared Linux/amd64 Docker release for the existing NAS installation,
not a native Windows or Mac installer. The source schema version remains 4.
The release version is supplied to `Initialize-Release.ps1`; local development
version defaults are unchanged. See [Releasing](../Releasing.md) for the
canonical source freeze, fresh backup/restore, full service/browser, security,
exact-image, upload, installation and rollback gates.

Build, qualification, publication and installation are pending. Historical
029/DF/SDK/fixture receipts do not qualify this release. Installed acceptance
will be recorded only after the exact release passes its gates and is verified
on the approved target.
