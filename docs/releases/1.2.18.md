# v1.2.18 - stable calendar loading, shareable filter links, faster cold discovery

## Calendar loading and stability

- The week board stays on screen while a week or filter change loads. Day
  columns show fixed-size placeholder cards instead of the board being replaced
  by a loading panel, and a screen-reader status line announces progress.
- Posters for the visible week are warmed on the server as soon as the calendar
  is ready (selected day first), and the adjacent weeks are prefetched at
  readiness instead of at the end of enrichment.
- Cards keep their order while details arrive. A load that ends with an
  item-cache validation error no longer leaves removed titles on screen.
- The filter catalog (genres, providers, languages, countries, certifications)
  now loads on every first-render path, including saved-filter restore and
  following a synced view.

## Links, sharing and week navigation

- Filter links are explicit again: language (`all` when empty) and the runtime
  range are always part of the URL, a URL that already carries a query is
  rewritten once to the canonical form, and Share copies that form. A plain
  URL keeps its saved-filter and view-sync behaviour.
- Previous week and Next week open the first day of that week; This week opens
  today. The board scrolls back to the start.
- View sync: reloading a tab follows the group when the group moved on after
  that tab last published; an explicitly opened filter link still wins. The
  per-tab record lives in session storage and is tied to the sync group.

## Languages

- Language codes are normalised before comparison (`nl-BE`, `nl-NL`, `vls`,
  `nld`, `dut`, "Flemish", "Dutch" all match `nl`), TVmaze's "Flemish" maps to
  `nl`, and the catalog labels the option "Dutch / Flemish (NL)".

## Cold discovery and OMDb

Cold discovery separates verified TMDb core metadata from optional ratings,
artwork and availability. Each source starts bounded enrichment after its own
pagination finishes while later sources keep discovering. Once complete core
coverage has been reconciled, eligible calendar views become ready and keep
receiving details through the existing SignalR observation. The readiness
check is read-only: it no longer accepts foreign rows into the load, and
anything it finds stale keeps the load partial instead of being published.
Readiness, once shown, stays shown for the rest of the load.

Final source checkpoints, complete-cache publication and durable job completion
still wait for their owned work. Provider request limits, all selected sources,
release occurrences and final filtering remain required. Filters that need
optional metadata retain complete mapping. Existing Series records needing core
refresh also retain the established full mapper to preserve optional metadata
and its provider ownership during failures.

OMDb's known data-retrieval and rejected-ID failures now have separate per-ID
retry deadlines of one and 24 hours. These deadlines persist across restarts;
healthy IDs remain independent, verified prior values survive, and explicit
force can retry earlier. No IMDb IDs or ratings are guessed. An upstream catalog
error may remain unavailable until OMDb recovers.

In matched cold fixtures measured on 7 November, movie readiness improved from
4.32 to 1.88 seconds and mixed-premiere readiness from 5.69 to 2.91 seconds.
These are single-iteration local fixtures, not production latency guarantees,
and were not re-measured after the readiness-check correction above.

## Runtime

The app, SDK image and runtime image move from .NET 11 RC3 to .NET 11.0.0 GA
(SDK 11.0.100). The first v1.2.18 candidate, still on RC3, was rejected before
any NAS load because the image scan reported three high and eight medium
.NET runtime CVEs that 11.0.0 fixes.

## Validation

Local validation on the exact release source passed 2,002 tests with one
expected Linux file-lock skip: 1,185 unit, 225 component and 592 integration
tests, the last including actual isolated PostgreSQL coverage. Tests never call
live providers.

Review: Claude Opus 5.5 (high effort) reviewed the calendar/UI changes and the
cold-discovery/OMDb changes adversarially in several rounds; all P0-P2 findings
were fixed and re-verified. Deviation from the v1.2.17 gate: no GPT-6 Astra
review was performed for this release. Known P3 follow-ups are scheduled for
v1.2.19.

Local builds, scans, SBOM and release publication do not use GitHub Actions.
Database contents, saved settings, application data and backups are preserved.

Windows host scripts that call `dotnet` now need .NET SDK 11.0.100 or later;
container builds are unaffected.
