# PremiereCalendar 1.2.14 — reliable selective cache refresh

Cached metadata, ratings and artwork now refresh independently. A failed optional provider preserves its own last-good fields and successful clock while other providers can apply corrections. Verified score withdrawal clears the corresponding values. Explicit refresh reaches optional providers while respecting shared quota and access-denial circuits. Stable identifier resolution can be reused during routine score refresh, and incomplete-provider retry windows no longer block unrelated metadata changes.

Concurrent rating writes merge provider payloads under the database transaction rather than replacing the whole ratings document. A successful provider cannot revert a newer independent provider result, and a newer verified empty response cannot be resurrected by an older fallback. IMDb dataset lookups have independent freshness, including an initially absent title becoming available later.

Series premiere rows retain the version reserved before asynchronous validation. Canonical-date checks use generation-bound shared work with independent caller cancellation; saved source checkpoints are reconciled before reuse. Fresh accepted date evidence can remove a postponed premiere from the old week, while later database winners and concurrent invalidations remain protected. Three-calendar-month database retention and the English/Dutch, premiere-only defaults remain unchanged.

An unavailable optional discovery source leaves an explicitly partial snapshot with a persisted coverage notice and visible warning. Otherwise validated results can be reused until its access-denial deadline. The scheduler finishes the degraded operation rather than repeatedly requeueing it; successful recovery clears the notice. Generation fences protect concurrent discovery and metadata maintenance. Nightly coverage is not falsely marked complete while a source is unavailable.

Mixed-country certification filters have independent cache identities even when TMDb cannot accept their full selection in one query. Text matching and cache normalization agree. Existing default English/Dutch cache identities are preserved. Real rate-limit responses, local deferrals, retained values and accepted component writes have distinct diagnostic outcomes.

Diagnostics record provider decisions, retry deadlines, component fetches, actual accepted projection changes/clears, rejected writes and precise reconciliation reasons, including media type, numeric item ID and measured duration. `eng/Read-CalendarPerformance.ps1 -CacheAudit` summarizes a session and explicitly reports missing, malformed, truncated or lost evidence. See [cache verification](../CacheFreshnessDiagnostics.md).

Release validation and installed measurements will be recorded after the local gates. Schema remains 4; no database restore is part of the app-only deployment. Builds, tests, security scans, SBOM and publication run locally; hosted workflows remain disabled.
