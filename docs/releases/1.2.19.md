# v1.2.19 - audit follow-up: steadier cards, safer failures, hardened settings and images

This release applies the findings of a full audit of the application and UI
done after v1.2.18.

## Calendar and UI

- One fixed-height status row above the board holds the cache state, the
  "updating details" notice and source warnings, so the board no longer moves
  when they appear or disappear. While a new week is checked the cache pills
  show a neutral "Checking cache..." instead of the previous week's state.
- Cards keep their height while details arrive: the ratings row is always
  present on one fixed line and the overview is clamped to three lines, with
  the full text under Details.
- A title whose identity resolves during a load replaces its earlier card
  instead of appearing twice.
- Details that arrive just before a load goes quiet are rendered by a trailing
  update, and a non-default sort is applied once when the load finishes.
- A plain link to the current week opens on today, and the selected day no
  longer changes by itself while a load is updating.
- The first posters of the selected day load eagerly with high priority.
- Keyboard focus is no longer pulled back to the heading during a load; the
  filter dialog returns focus to its opener after Save.
- Screen readers get one concise status line instead of constantly changing
  progress regions; error messages stay until dismissed.
- The filter dialog keeps its option lists steady during a load, merges
  regional language codes into one row and shows the filter catalog when it
  arrives while the dialog is open.
- Dark-theme overview text meets contrast requirements; the compact density is
  applied before first paint.

## Loading pipeline

- A provider failure is no longer saved as a complete week. A failed or
  throttled TVmaze schedule keeps the days that loaded, reports the source as
  failed with its retry time and leaves the week partial. TMDb throttling or a
  timeout while matching an external title no longer creates an "unverified"
  card; titles that did match stay on screen and the source is retried.
- After the calendar is ready, a later enrichment error no longer brings
  expired cards back for one update.
- A single item-cache read failure is a timed backoff that the same load can
  recover from, instead of failing the load.
- The provider response cache allows 1.5 seconds per read or write (was 0.5)
  and backs off only after three failures within ten seconds; optional
  providers treat an unavailable cache as a miss.
- Series candidates are checked against the language filter after the core
  step, before ratings and availability are fetched; regional codes such as
  `nl-BE` are normalised everywhere.
- Posters that are already at or below the requested width are stored and
  served as they are instead of being re-encoded; four images can be decoded
  at once and two workers warm posters.
- Cards have a stable order between visits (final tie-break on identity), the
  readiness check no longer turns a failed validation read into a partial
  load, and adjacent-week prefetch keeps the priority date.

## Settings, images and hosting

- Importing a settings backup keeps stored API keys and tokens when the backup
  is redacted or a secret is blank, and rejects incomplete backups instead of
  resetting settings to defaults.
- Secret fields on the Settings page are write-only: stored keys and tokens are
  never sent to the browser. A blank field keeps the stored value, typing
  replaces it and Clear removes it. A stored Sonarr or Radarr key is not reused
  after its server URL changes.
- The image endpoint serves only verified raster images (JPEG, PNG, GIF, WebP,
  AVIF) with sandboxing headers, returns empty-bodied errors, no longer accepts
  a public refresh switch and snaps the requested width to the widths the app
  uses. Image redirects are followed only within the allowed hosts.
- `compose.yaml` sets the Europe/Brussels time zone, rotates container logs
  and gives the app 20 seconds to stop.

## Not in this release

An optional "new seasons" series filter needs season-premiere discovery from
the providers and is planned as its own release. Windows installer and updater
findings (service port and environment kept across updates, logs and backups
under the data root) are open.

## Validation

Local validation on the exact release source passed 2,183 tests with one
expected Linux file-lock skip: 1,283 unit, 271 component and 629 integration
tests, the last including actual isolated PostgreSQL coverage. Tests never call
live providers. Two wall-clock-sensitive unit tests and two filter-dialog
component tests were made independent of host load.

Implemented by Claude Sonnet 5.5 (medium effort) and reviewed adversarially by
Claude Opus 5.5 (high effort) per package, with fix and re-review rounds until
no P0-P2 finding remained open. No GPT-6 Astra review was performed, as for
v1.2.18.

Local builds, scans, SBOM and release publication do not use GitHub Actions.
Database contents, saved settings, application data and backups are preserved.
