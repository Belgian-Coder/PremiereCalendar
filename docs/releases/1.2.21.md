# v1.2.21 - macOS lock portability and faster local validation

## Changes

- Calendar cache publication treats errno 35 (`EWOULDBLOCK` on macOS) as lock
  contention on macOS only, so concurrent publication waits instead of failing
  there. Linux and Windows behaviour is unchanged: the installed Linux
  container keeps the same lock handling as v1.2.20.

## Local build, test and release harness

- WSL builds and tests read source from a content-hash-verified ext4 mirror of
  the checkout instead of the slower `/mnt/d` mount; results stay in the
  checkout. A no-change rerun of the warm test build dropped from about 240 s
  to 15 s.
- For development feedback, identical inputs (all source bytes, image,
  selection, scheduling, configuration and the UTC date) reuse an earlier
  passing test run. Release gates never reuse: the release test step always
  runs its own suites (`-NoCache`) on the WSL lane.
- The mirror fails closed (stray files, extraction failures), test cleanup
  tolerates a saturated shared Docker engine (longer bounded calls), and the
  release receipt records the real PostgreSQL CPU quota.
- `Invoke-Validation -Changed` runs only the test classes that reference the
  changed types, with safe fallbacks to whole suites.
- The throwaway test PostgreSQL scales with the runner budget and has longer
  timeouts; two load-sensitive tests were made robust. The three service
  suites run in about 4.5 minutes on the WSL builder.
- macOS runs a native feedback lane (host .NET SDK and a throwaway local
  PostgreSQL); release acceptance stays on the Windows/WSL linux/amd64 builder.
- `tests/HarnessPolicy.Tests.ps1` enforces these defaults and the AGENTS.md
  rules in the static lane.

## Release boundary

The database schema stays at version 4, so an app-only rollback to 1.2.20 is
possible. Installed acceptance is recorded after the exact release passes its
gates and is verified on the NAS.
